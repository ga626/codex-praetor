# Codex Praetor 0.16.12-alpha

## 发布内容

- 新增面向当前 Codex 对话和当前项目的 **Codex 执行官模式**。用户可说“开启 Codex 执行官模式”或简称“开启执行官模式”，让后续实质任务先评估是否存在适合 Qoder 或 CodeBuddy 的受控外派阶段。
- 新增开启、状态、关闭三个稳定 MCP 工具。关闭时只正式取消同一对话、同一项目、同一模式会话启动的活跃 worker；未取得终态不会伪报模式已关闭。这一过程保留 structured progress（结构化进展）和 formal cancellation（正式取消）合同，供宿主和验收工具准确判断状态。
- 每个模式派工将模式会话标识写入任务元数据；不会把原始对话 ID、提示词、认证资料或隐藏思维写入项目状态。
- MCP 工具默认输出中文短摘要，并保留结构化详情。摘要如实显示当前动作、Qoder 或 CodeBuddy、实际模型、连接方式和 Codex 下一步；稳定 `codex_praetor_*` 机器工具名不变。
- 插件展示名更新为“Codex 执行官”。`Codex`、`Qoder`、`CodeBuddy` 等技术名称保留原名，不附加厂商或地区标签。

## 用户影响

- 这不是自动派工或自动合并。Codex 仍先定义范围、执行 dry-run、授权、验收和整合；不能外派的阶段由 Codex 自己完成。
- 模式严格限于当前对话与当前项目；新对话和其他项目不会继承。
- 本版不新增 provider、模型、认证访问、生产侧动作或原生 Codex subagent 路线。

## 验证

- 模式政策读写、对话哈希隔离、重复开启、关闭、路由和误触发反例均有确定性回归。
- 最终 artifact 必须验证新增 MCP 工具、合同、Skill 镜像、中文摘要、Qoder/CodeBuddy 真实任务和发布安装链。

## 已知宿主边界

- Codex Desktop 是否采用 MCP `title` 来渲染外层工具卡由宿主决定；本版不承诺改变该固定卡片，但每次工具结果都会提供中文短摘要。
